# Макс і код маяка 🗼

Інтерактивна дитяча книга, яка вчить не лише Python, а й **як думає комп'ютер і як
думати, як програміст** — через історію про хлопчика Макса, який лишився сам доглядати
маяк, поки його кіт Цугі поїхав до друга в Японію.

Дитина читає розділ, розбирає команду на частини, дивиться блок-схему — а тоді пише
**справжній Python** у вбудованій пісочниці, і маяк на екрані оживає. Помилки
перекладаються спокійним голосом світу маяка українською.

## Що всередині

- **Історія** — «Від Макса», пролог, шість розділів (від списку-алгоритму до ночі шторму)
  та епілог, з листівками від Цугі з Японії.
- **Банки з насінням** — доглядач рахував ночі насінням у підписаних банках, а Макс завів
  свою, четверту: «пельмені» (Цербер з'їдає три за раз — по одному на голову). Банки стоять
  на підвіконні ліхтарної кімнати й видно їх просто біля маяка в пісочниці.
- **Розбір команд** — кожна команда «розкладена» на частини з підписами.
- **Блок-схеми** — з поясненням фігур (овал, прямокутник, ромб, стрілка).
- **Справжня пісочниця** — Python у браузері через [Pyodide](https://pyodide.org),
  з українськими командами маяка та дружніми повідомленнями про помилки.
- **Завдання** — 13 місць, де код пише вже дитина: порожня пісочниця, мета, дві підказки
  й «підглянути в журнал доглядача». Маяк сам перевіряє результат і відповідає підказкою,
  а не оцінкою. Зроблене отримує зірку ★.
- **Завдання «У житті»** — перенесення способу мислення поза екран, із галочкою «я спробував».

## Де живе текст

Увесь текст книги — в **одному файлі**, `content/story.js`. Там немає логіки: лише історія,
розбори, схеми й приклади коду, розкладені на блоки (`story`, `journal`, `sb`, `applied`…).
Розмітку з нього робить `js/book.js`, а `index.html` — то вже просто обкладинка з місцем,
куди книга вкладається.

Щоб змінити або дописати розділ — міняється тільки `content/story.js`.

Щоб перечитати самий текст, без коду й тегів:

```bash
node tools/manuscript.mjs      # → content/story.md (рукопис для вичитки/друку)
```

## Як улаштовані завдання

Завдання живе там само, де текст — у `content/story.js`, блоком `{t:'task'}`:

```js
{ t:`task`, id:`t3-1`, title:`Ніч без тебе`,
  goal:`Що саме має статися з маяком…`,
  code:`запалити_вогонь()\n`,          // з чого дитина починає
  hints:[`перша підказка`, `друга`],
  solution:`…`,                        // під «підглянути в журнал доглядача»
  checks:[{r:`uses`, what:`while`}, {r:`calls`, what:`rotate`, min:6}],
  trials:[{ label:`сильний вітер`, world:{wind:`сильний`}, checks:[{r:`light`, is:`dim`}] }] }
```

`checks` — це правила, які маяк перевіряє після запуску. Самі правила описані в
`js/tasks.js`, і кожне вміє сказати дитині, чого бракує, її ж словами:

| правило | про що воно |
|---|---|
| `lit` | маяк узагалі засвітився |
| `order` | кроки пішли в потрібному порядку |
| `calls` | скільки разів покликано команду (`min` / `max` / `is`) |
| `lens`, `light` | куди дивиться лінза, яким лишилось світло |
| `jar` | скільки лишилось у банці (`запас`, `пельмені` або своїй) |
| `newJar` | дитина завела власну банку |
| `printed` | щось (або щось конкретне) сказано в журнал |
| `uses` | у коді справді є `while`, `for`, `def`, `if`, `return`, параметр… |
| `habit` | звичка з таким іменем і оголошена, і покликана |
| `watered` | полито всіх соняшників |

`trials` — це та сама програма, тихо прогнана в іншу погоду (або з іншим пальним).
Так перевіряються завдання про вибір: маяк сам ганяє код крізь усі гілки.

Коли додаєш нове завдання — проженeш сторожа:

```bash
node tools/check-tasks.mjs
```

Він бере авторський розв'язок кожного завдання, виконує його справжнім прологом маяка
(звичайним `python3`) і перевіряє, що той проходить свої ж `checks` і всі `trials` —
а стартовий код, навпаки, не проходить і нікуди не падає.

Зірки зберігаються в `localStorage` під ключем `lighthouse_done`. Скинути:

```js
localStorage.removeItem('lighthouse_done')
```

## Технічно

Статичний сайт — жодного бекенду. Python виконується у браузері (WebAssembly, Pyodide,
завантажується з CDN jsDelivr при першому запуску коду). Кожен запуск отримує чистий
простір імен, тож пісочниці не підглядають одна в одну.

```
index.html          # обкладинка книги (текст сюди не пишемо)
sandbox.html        # вільна пісочниця + довідка команд
content/story.js    # ← УВЕСЬ ТЕКСТ КНИГИ
css/style.css
js/book.js          # малює книгу з content/story.js
js/tasks.js         # перевірка завдань + журнал зірок (localStorage)
js/lighthouse.js    # SVG-маяк, банки з насінням, програвання дій
js/runtime.js       # Pyodide, команди маяка, переклад помилок
js/gate.js          # двері маяка (купон)
tools/manuscript.mjs# експорт чистого тексту в content/story.md
tools/check-tasks.mjs # сторож завдань: чи розв'язки ще проходять перевірки
```

## Запустити локально

Через будь-який статичний сервер (Pyodide не працює з `file://`):

```bash
python3 -m http.server 8000
# відкрити http://localhost:8000
```

## Публікація на GitHub Pages

1. Запуш цей репозиторій на GitHub (див. нижче).
2. Settings → Pages → Build from branch → `main` / root.
3. Сайт буде доступний за адресою `https://<user>.github.io/lighthouse-code/`.

## Запушити в репозиторій

Репозиторій уже ініціалізований, з першим комітом і доданим `origin`.
З твоєї машини лишилось тільки:

```bash
git push -u origin main
```

## Доступ за купоном

Перед книгою — «двері маяка»: читач вводить ключ-купон. Наразі купон
захардкоджено в `js/gate.js`:

```js
const VALID = ['tsugi26'];   // тут можна додати ще купони
```

Після правильного введення факт розблокування зберігається в `localStorage`,
тож наступного разу двері не з'являються.

**Скинути доступ** (для перевірки) — у консолі браузера:

```js
localStorage.removeItem('lighthouse_unlocked')
```

> ⚠️ Це **м'яка завіса на боці браузера**, а не справжній захист: купон видно в
> коді сторінки, і його можна обійти. Для реального продажу купон треба перевіряти
> на сервері (наприклад, невелика serverless-функція, що видає одноразовий токен).
